# HW12 – временные ряды: temporal split, baseline-модели и GRU-прогноз

## 1. Кратко: что сделано

- **Датасет**: `S12-hw-dataset.csv` – временной ряд с часовой периодичностью (4320 наблюдений) за период с 01.01.2025 по 29.06.2025.
- **Целевая переменная**: `target` – прогнозируемый числовой ряд.
- **Разбиение**: выполнено корректное временное разбиение на `train` (80%), `validation` (10%), `test` (10%) с сохранением хронологического порядка.
- **Сравниваемые подходы**:
  - **B1** – Naive baseline (прогноз = последнее известное значение)
  - **B2** – Moving Average с окном 24 часа
  - **B3** – Ridge regression на лаговых, rolling и календарных признаках
  - **R1** – GRU с оконным представлением (window_size=24)
- **Лучший подход**: **B3 (Ridge regression)** показал наилучший результат на валидации (MAE=5.2379). Финальная оценка на тесте: MAE=5.4227.

## 4. Temporal split и признаки

### 4.1. Разбиение по времени

- **Разбиение**: первые 80% данных – train, следующие 10% – validation, последние 10% – test.
- **Границы**: Train: 2025-01-01 – 2025-04-20 (3456), Validation: 2025-04-20 – 2025-05-10 (432), Test: 2025-05-10 – 2025-06-29 (432)
- **Почему random split некорректен**: временные ряды имеют автокорреляцию, random split нарушил бы временную структуру и создал бы утечку данных из будущего.

### 4.2. Признаки для baseline-моделей

- **Лаги**: `lag_1`, `lag_7`, `lag_14`
- **Rolling-признаки**: `rolling_mean_7`, `rolling_std_7`
- **Календарные признаки**: час, день недели, день месяца, месяц, а также синус/косинус для цикличности
- **Обработка пропусков**: строки с NaN удалены
- **Масштабирование**: StandardScaler, обученный только на train

## 5. Модели и эксперименты (B1, B2, B3, R1)

- **B1 (naive-last)**: прогноз равен последнему известному значению.
- **B2 (moving-average)**: скользящее среднее с окном 24 часа.
- **B3 (ridge-lag-features)**: линейная регрессия с L2-регуляризацией на 11 признаках. alpha=1.0.
- **R1 (gru-forecast)**: двухслойная GRU с hidden_dim=64, dropout=0.2, window_size=24. Обучение 100 эпох, сохранение лучшей модели по валидационному loss.

**Основная метрика выбора**: MAE на валидации.
