# HW14 – эмбеддинги, FAISS, оценка retrieval и mini-RAG по базе знаний

## 1. Кратко: что сделано

- Использована учебная база знаний из 10 документов по NumPy, pandas и Matplotlib, так как по ней удобно задавать вопросы о работе с данными и визуализацией.
- Чанкинг выполнен по предложениям, что даёт короткие и осмысленные фрагменты.
- Для векторизации использована модель `sentence-transformers/all-MiniLM-L6-v2`.
- Базовая проверка retrieval показала высокое качество: `hit@5 = 1.0`, `MRR@5 = 0.938`.
- После обновления базы знаний (добавлены 3 новых документа) retrieval изменился для части запросов.
- Mini‑RAG корректно формировал ответы на основе найденного контекста и возвращал источники.

## 3. База знаний и подготовка документов

- **Предметная область:** основы NumPy, pandas и Matplotlib.  
- **Источник документов:** учебные текстовые описания (10 документов).  
- **Число исходных документов:** 10  
- **Число чанков после разбиения:** 13  
- **Способ чанкинга:** разбиение текста на предложения.  
- **Основные параметры:** один чанк = одно предложение, overlap = 0.

**Комментарий:**  
База знаний компактная, тематически однородная и хорошо подходит для retrieval-задачи. Документы короткие, поэтому разбиение на предложения даёт осмысленные чанки. Тематика позволяет задавать естественные вопросы (про groupby, merge, broadcasting, стили графиков). Такой корпус удобен для построения учебного mini‑RAG.

## 4. Retrieval и индекс

### 4.1. Эмбеддинги и индекс

- **Embedding-модель:** `all-MiniLM-L6-v2`  
- **Метрика сходства:** cosine similarity через inner product  
- **Индекс FAISS:** `IndexFlatIP`  
- **top_k по умолчанию:** 5  
- **Первые примеры retrieval:** релевантные документы стабильно попадали в top‑5 (например, запрос про groupby → `pandas_groupby`).

### 4.2. Контрольные запросы и оценка retrieval

- **Количество контрольных запросов:** 8  
- **Что считалось релевантным:** документ, соответствующий теме вопроса  
- **Метрики:** `hit@k`, `recall@k`, `MRR@k`  
- **Итоговый hit@5:** **1.0**  
- **Итоговый recall@5:** **1.0**  
- **MRR@5:** **0.938**  
- **Самые простые запросы:** про groupby, merge, broadcasting  
- **Самые сложные:** более общие вопросы про визуализацию

## 5. Эксперимент по параметрам retrieval и обновление базы знаний

- **Сравниваемый параметр:** `top_k`  
- **Варианты:** `top_k = 3` и `top_k = 5`  
- **Изменение качества:** в этой базе знаний оба варианта дали `hit@k = 1.0`, но `top_k = 5` даёт более устойчивые результаты.  
- **Выбранный вариант:** `top_k = 5`  
- **Что обновлено:** добавлены 3 новых документа (`matplotlib_subplots`, `matplotlib_legends`, `numpy_performance`)  
- **Переиндексация:** выполнена заново — чанкинг → эмбеддинги → новый FAISS  
- **Изменения retrieval:** для части запросов появились новые релевантные документы (особенно по Matplotlib)

## 7. Анализ

Выбранная база знаний оказалась удачной: она компактная, однородная и позволяет формулировать понятные вопросы. Чанкинг по предложениям дал короткие и точные фрагменты, что улучшило retrieval. Формальная оценка retrieval показала высокое качество и позволила убедиться, что модель корректно сопоставляет запросы и документы. Эксперимент с `top_k` показал, что увеличение числа кандидатов делает retrieval более устойчивым. Обновление базы знаний улучшило ответы mini‑RAG на вопросы про Matplotlib. Ошибки mini‑RAG чаще всего были связаны с тем, что retrieval находил слишком общие фрагменты или несколько равнозначных. Ограничения решения — маленький корпус, отсутствие reranking и простой генератор ответов.

---

## 8. Итоговый вывод

Базовый retrieval-конвейер для такой задачи: чанкинг по предложениям → `all-MiniLM-L6-v2` → `FAISS IndexFlatIP` → `top_k = 5`. Главное наблюдение: качество retrieval критически влияет на итоговый ответ mini‑RAG. Если релевантный контекст найден, даже простой генератор даёт полезный ответ; если нет — mini‑RAG ошибается. Связка retrieval + контекст + генерация работает только при корректной индексации и хорошей базе знаний.
